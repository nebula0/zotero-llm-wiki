# 文獻管理系統：規則

> 人和 AI 共同參考的規則。lit-library 和 lit-reading 兩個 skill 只寫「怎麼做」，規則以本檔為準。
> 核心原則：**一篇一頁＋Bases 檢視；文章頁完全由程式重建，人和 Claude 都不直接編輯**（第 0 節）。

---

## 0. 文章頁與重建

**原則：人不編輯，行為觸發。** 文章頁與表格是「輸出」，由重建腳本從「輸入」產生，任何人（含 Claude）都不直接編輯；壞了就重建。

| 輸入（唯一真相） | 內容 |
|---|---|
| Zotero 裡的行為 | 畫記、tag、筆記、存新文章（使用者） |
| 紀錄（只追加） | 來源紀錄、決策紀錄、AI 閱讀紀錄（Claude 依搜尋結果或使用者的話寫入） |
| 外部資料 | OpenAlex 原始書目快取、AI 筆記、任務檔 |

| 檔案 | 變動 | 說明 |
|---|---|---|
| `2_paper/文獻庫/{citekey}.md` | 程式重建 | **文章頁**：檔頭屬性＝固定資料＋狀態；內文＝主要貢獻、為何抓、相關連結。頂端標示「自動產生，請勿編輯」 |
| `2_paper/任務/{任務代號}.md` | 程式重建 | **任務頁**：目的 → 結果（要讀／候選／已排除與理由，每篇附摘要）→ 搜尋過程（每次查詢的資料庫、字串、結果數、收了哪幾篇） |
| `2_paper/待匯入/{任務代號}.md` | 暫存 | **匯入前預覽**：`import-batch --preview` 產生，版型同任務頁，新文章標 🆕；使用者看過才匯入，匯入時自動刪除 |
| `2_paper/文獻庫.base` | 幾乎不變 | 只定義顯示方式（表格、卡片牆、各種篩選檢視），不存資料 |
| `2_paper/notes/{citekey} 閱讀卡.md` | Zotero 匯入 | 使用者的畫記與筆記（Obsidian 的 Zotero Integration 外掛匯入） |
| `1_attachment/封面/{citekey}.jpg` | 程式重建 | 文章頁封面（卡片牆顯示） |
| `2_paper/AI筆記/{citekey} AI筆記.md` | Claude 追加 | Claude 讀這篇的筆記：整體摘要＋問答紀錄；文章頁自動連過來。流程見 `lit-reading` skill |
| `2_paper/文獻庫資料/` | 只追加 | 紀錄檔與 OpenAlex 快取，格式見第 11 節 |

- **封面**：有 PDF 就有封面，重建時依序取 ① Zotero 框選圖（「選擇區域」）中評論開頭為 `cover` 的那張 ② 第一張框選圖 ③ 自動：前 3 頁最大的點陣圖，沒有就截第 1 頁上方。
- **連結**：Bases 表格第一欄即文章頁；文章頁連到閱讀卡；任務、AI 筆記、概念頁以 `[[citekey]]` 連到文章頁，自動出現在反向連結。
- **重建**：只在內容真的改變時才寫檔；Claude 做文獻相關工作前先重建一次。Zotero 那邊的變動（新文獻、標註、封面框選）要重建才會反映。
- **規則寫在 skill，保證寫在程式**：寫入一律透過腳本，不手動改檔頭。

## 1. 文章固定資料

一律從 OpenAlex／Crossref 抓，不由 AI 憑記憶填。

| 欄位 | 說明 |
|---|---|
| citekey | 給人看的代碼，見第 6 節 |
| 去重鍵 | DOI（Digital Object Identifier，數位物件識別碼）；沒有時用 arXiv 編號或 OpenAlex 編號 |
| 書目 | 標題、作者、期刊、年份、文章類型 |
| 摘要、原始關鍵字 | 原始關鍵字與自訂 tag 分開存 |
| 參考文獻 | 這篇引用了誰（算庫內引用關係） |

## 2. 文章狀態

每個欄位都由某個輸入推導出來，沒有手寫欄位。

| 欄位 | 從哪個輸入推導 | 說明 |
|---|---|---|
| 狀態 | 決策紀錄 | 候選／要讀／已排除（附理由）；Claude 初判寫入，使用者說了算 |
| **主要貢獻** | AI 閱讀紀錄 | 一句話；附依據等級；AI 讀得更深時追加新的一筆，頁面顯示最新 |
| **為何抓** | 來源紀錄 | 一次發現一行，附日期與任務 |
| 標籤 | 標籤紀錄＋Zotero tag＋本團隊 | **英文、固定詞表**（`設定.json`）：`topic/…` 主題、`type/…` 類型，另加本團隊 tag。Claude 依摘要分；詞表外的 tag 程式會擋 |
| 全文取得狀態 | OpenAlex＋Zotero | 有免費版（附連結）／需要授權／已在 Zotero |
| AI 閱讀程度 | AI 閱讀紀錄 | 見第 7 節；須連到留存的 AI 筆記才算數 |
| 閱讀跡象 | Zotero | 標註數（依顏色）、評論數、標註頁數比例、最後開啟日期 |
| 人類閱讀程度 | Zotero | 由閱讀跡象推斷；推斷錯時以 Zotero tag `閱讀/…` 覆寫（第 7 節） |
| 被引次數 | OpenAlex | 附查詢日期 |
| 本團隊 | 作者名單＋`設定.json` | 作者含 `設定.json` 裡的本團隊成員即標記 |

## 3. 任務

- 文章與任務多對多；任務是容器（搜尋、整理、閱讀、寫作都算）。
- 關係：找到（附來源紀錄）、排除（附理由）、閱讀、使用（角色：論點／實驗／理論／綜述；必引度 ★～★★★）。

## 4. 來源紀錄

只追加、不修改。每篇文章至少對應一筆。

| 類型 | 由誰寫 | 記什麼 |
|---|---|---|
| 關鍵字搜尋 | Claude | 日期、任務、資料庫（OpenAlex 或 WebSearch）、查詢字串、年份、結果數、收錄與排除清單 |
| 引用追蹤 | Claude | 起點文章、方向（往前：它引用誰／往後：誰引用它） |
| 手動加入 | 自動 | Zotero 有、庫裡沒有的條目；日期取 Zotero 加入日期 |

## 5. 標註規範

### 5.1 人類標註

| 顏色 | 意思 |
|---|---|
| 🟡 黃 | 核心論述、要引用的句子 |
| 🔴 紅 | 懷疑、不同意 |
| 🟢 綠 | 方法值得參考 |
| 🔵 藍 | 關鍵數據 |
| 🟣 紫 | 還需要查資料（＝待查） |

### 5.2 AI 標註

- **顏色一律灰色 `#aaaaaa`**（Zotero 調色盤的灰色）。人類不使用灰色。
- **分類用 tag**，與人類的顏色分類平行，另加一類「本研究」：

| AI tag | 對應人類顏色 | 意思 |
|---|---|---|
| `AI/論點` | 🟡 | 核心論述、主要貢獻所在的句子 |
| `AI/質疑` | 🔴 | 可疑、與其他文獻矛盾、證據不足 |
| `AI/方法` | 🟢 | 值得參考的方法 |
| `AI/數據` | 🔵 | 關鍵數字 |
| `AI/待查` | 🟣 | 需要核對或追查的引用 |
| `AI/本研究` | — | 與使用者研究主題（`設定.json` 的「研究主題」）直接相關 |

- **範圍：整段標**：一則標註框住評論所依據的完整論述（前因、主張、作者的理由或限定，通常 2～5 句，不跨頁）。同一段裡不同論點才拆成多則；相鄰的不要重疊。
- **評論**：一到兩句說明為什麼標，句子用中文、專有名詞用英文；和特定任務有關時，結尾加 `〔任務：…〕`。
- **何時標**：回答使用者對某篇論文的問題時，自動標出回答引用的原句，不用先問；評論開頭加 `〔問：…〕`。其他情況下 Claude 主動想標，要先問。
- **權限**：AI 只能新增、刪除自己的灰色標註，不動人類標註。
- **人類採納**：把 AI 標註改成自己的顏色 = 採納（`AI/` tag 保留）；刪掉 = 不採納。
- **寫入方式**：透過 Zotero 網路 API（Application Programming Interface，應用程式介面）寫進 Zotero，同步回桌面版。需要使用者的 Zotero API 金鑰，且 Zotero 要開啟同步。

## 6. 代碼與去重

- DOI 給機器去重；citekey 給人看（檔名、`[[連結]]`、`\cite{}`）。
- citekey 由 Better BibTeX（BBT）產生，公式 `auth.lower + shorttitle(3, 3) + year`，存在 Zotero 的 Citation Key 欄位，一律固定。
- 尚未進 Zotero 的候選：用同公式產生暫定 citekey；存進 Zotero 後改用正式 citekey，舊頁刪除。

## 7. 閱讀程度

| 等級 | AI | 人類 |
|---|---|---|
| 0 | 只有書目 | 沒看 |
| 1 | 讀摘要 | 看過標題 |
| 2 | 讀部分內文（引言、圖、結論） | 讀過摘要 |
| 3 | 讀全文 | 略讀 |
| 4 | — | 精讀 |

- AI 閱讀須記錄讀的版本（預印本／期刊版）。
- 人類自動推斷：沒開過 → 0；開過、沒標註 → 1；有標註但分布未過全文一半頁數 → 2；過半 → 3；過半且有評論或筆記 → 4。只計人類的彩色標註；帶 `paper-chat` 標籤的標註和筆記是 Paper Chat 外掛產生的，不算。
- 推斷錯時，在 Zotero 對該條目打 tag：`閱讀/沒看`、`閱讀/看過標題`、`閱讀/看過摘要`、`閱讀/略讀`、`閱讀/精讀`（對應 0–4）。

## 8. 判斷依據

依據等級（由強到弱）：全文 > 摘要 > 他人描述（引用句、綜述、搜尋引擎片段）> 僅書目 > AI 記憶。

- 值得看：僅書目即可，AI 可自行列候選。
- 值得引用：須有全文對應段落；AI 提議、使用者確認。
- 依據只有「僅書目」或「AI 記憶」的，不給必引度。

## 9. 全文取得

1. OpenAlex 查合法免費版本（arXiv、機構典藏），有就讀那個版本。
2. 沒有 → 使用者用瀏覽器＋Zotero Connector 存入 Zotero。
3. 不以程式大量下載期刊 PDF（出版社會擋，且違反授權條款）。

## 11. 檔案格式與位置

```
2_paper/
├─ 文獻庫/{citekey}.md        文章頁（程式產生）
├─ 任務/{任務代號}.md         任務頁（程式產生）
├─ 文獻庫.base                表格／卡片檢視
├─ notes/{citekey} 閱讀卡.md   閱讀卡（Zotero 匯入）
├─ AI筆記/{citekey} AI筆記.md  AI 筆記（Claude 讀文獻時追加）
└─ 文獻庫資料/                 輸入
   ├─ 任務 搜尋 來源 決策 AI閱讀 標籤 .jsonl   紀錄，只追加
   ├─ openalex/{DOI}.json     OpenAlex 書目快取
   └─ 設定.json               研究主題、本團隊名單、標籤詞表
```

- **工具** `litlib.py`：`rebuild` 重建、`find` 搜前查庫、`fetch` 查 OpenAlex、`search` 關鍵字搜尋、`track` 引用追蹤（搜尋結果標出已在庫內 ★／已排除 ✗）、`log` 追加單筆紀錄、`import-batch` 匯入搜尋批次。
- **摘要來源**：依序 OpenAlex → arXiv → Semantic Scholar → Crossref。不是從 OpenAlex 讀到的，填「摘要來源」；只看到搜尋引擎片段或工具轉述的，依據降為「他人描述」。
- **紀錄只能用 `log` 或 `import-batch` 寫**，它們會檢查必填欄位與下列規則，不合格整批不寫。
- **紀錄格式**：每行一筆 JSON（JSONL）。`日期` 省略時自動填當天。`文章` 填 DOI，沒有 DOI 時填 `zotero:條目代號` 或 `openalex:W…`。

| 紀錄 | 必填 | 選填 | 程式檢查 |
|---|---|---|---|
| 任務 | 代號、名稱、類型（搜尋／整理／閱讀／寫作） | 說明、筆記（`[[…]]`） | 代號不可重複；其他紀錄的「任務」必須先登記 |
| 搜尋 | 任務、方式（關鍵字搜尋／引用追蹤） | 資料庫、查詢、年份、期刊、結果數、起點、方向（往前／往後）、說明 | 代號自動產生 `S20261001-1`；關鍵字搜尋要有查詢，引用追蹤要有起點與方向 |
| 來源 | 文章、方式（關鍵字搜尋／引用追蹤／使用者提供／舊清單）、為何抓 | 任務、搜尋 | 來自搜尋的必須附存在的搜尋代號 |
| 決策 | 文章、由（AI／使用者） | 狀態（候選／要讀／已排除）、理由、任務、角色（論點／實驗／理論／綜述）、必引度（1–3） | 排除要附理由；AI 給必引度前須有依據為全文／摘要／他人描述的 AI 閱讀紀錄 |
| 標籤 | 文章、由，加或移除（list） | 理由 | tag 必須在詞表內 |
| AI閱讀 | 文章、程度（0–3）、依據、主要貢獻 | 版本（期刊版／預印本／會議版）、筆記、摘要來源 | 程度 2 以上要附筆記；程度 3 的依據須為全文 |

- **重建時的推導**：
  - 文獻庫 = Zotero 條目（略過沒有標題也沒有 DOI 的空白條目）＋紀錄裡出現的文章。
  - 狀態取最新決策；沒有決策時，在 Zotero 的預設「要讀」，其餘預設「候選」。
  - 主要貢獻取最新 AI 閱讀紀錄；AI 閱讀程度取最高。
  - 發現日取來源紀錄與 Zotero 加入日期中最早的。
  - 引用關係由 OpenAlex 參考文獻比對，只列庫內文章。
- **OpenAlex 快取**：第一次查詢後存檔，之後不重抓；`rebuild --refresh` 才更新被引次數。
- **移除**：文章頁對應的條目消失時（從 Zotero 刪除或 citekey 改名），重建會刪掉舊頁並列出，提醒更新其他筆記的連結。
